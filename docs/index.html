Can Search Signals Help Editors Prioritize Content for Refresh Review?

An explainable ranking experiment on an anonymized search-performance snapshot

Author: Albert Michael Tigo · Dataset: 30,000 content rows · 32 pseudonymous clients

Abstract

This project asks whether observable content and search signals can help an editor prioritize pages for refresh review. It uses the 30,000-row anonymized FlyRank starter snapshot, with one row per pseudonymous content item and 32 pseudonymous clients. A transparent stale-and-visible rule is compared with logistic regression, a decision tree, and a random forest using a client-holdout evaluation where available. The committed pipeline report records a random-forest ROC AUC of 0.750 and Precision@50 of 0.740, compared with 0.627 and 0.240 for the rule baseline; the overall declining-label rate is 0.542. These results are decision-support evidence on a cross-sectional snapshot, not proof that refreshing a page will improve traffic and not a validated forecast of future decline.

Important interpretation: the 90-day model inputs overlap the 30-day window used to derive the decline label. This is a contemporaneous classification/ranking exercise, not a clean past-to-future prediction.

1. Introduction and problem

Editors have more pages than they can manually inspect. The unit of analysis is one content item. The system outputs a ranked review queue, score, suggested action, confidence band and reason codes. An editor uses it to decide which pages to inspect first; the system does not publish or rewrite pages automatically.

A false positive costs editorial review time. A false negative may leave a potentially useful page unreviewed. The ranking is a triage aid, not an automated decision.

2. Data and safety

The starter snapshot contains 30,000 rows × 44 source columns and 32 pseudonymous clients. The reference target is is_declining_label, derived from trend_direction == "down"; 16,262 rows are positive (54.2%). Pseudonymous content and client IDs are used for grouping only, never as predictive features.

The model excludes trend_direction and trend_pct, which directly define or encode the label. It also excludes client/content IDs, provider/model names and product-decision flags. No raw client names, domains, URLs, titles or search queries are used or published.

3. Baseline

The baseline flags pages at least 180 days since their last update and with at least 500 impressions in the observed 90-day window. Its score is stale × visible × impressions_90d. Its reason code is stale_and_visible; its action is review_refresh. The saved baseline notebook observed 17 actionable pages among 30,000.

4. Model and methodology

The reference pipeline prepares features, creates the baseline, trains logistic regression, a depth-limited decision tree and a random forest, then exports a ranked queue. The random forest uses 200 trees, maximum depth 10, minimum leaf size 25, balanced subsampling and random seed 42. The training script attempts a client-level holdout (about 20% of clients); the committed report says client_holdout was used.

The split reduces direct client overlap between train and test. It does not fix the temporal overlap between the feature window and the label window. The target is a proxy for observed decline in this snapshot, not a verified editorial outcome.

6. Limitations and honest framing

  1. The target is a proxy derived from a short-term trend category, not a human-labelled refresh success outcome.
  2. The single-snapshot feature windows overlap the label-construction period. This prevents a future-prediction claim.
  3. The starter slice has 30,000 rows and 32 pseudonymous clients; results may not generalize to the full warehouse, other clients or later periods.
  4. A client holdout tests transfer to held-out clients within this snapshot, not transfer across time.
  5. Feature importance is associative, not causal. It does not show that refreshing a page will improve performance.
  6. Confidence bands are triage labels, not calibrated probabilities of editorial success.

Supported claim: on the reported held-out split of this anonymized snapshot, the random forest ranked the proxy-declining label more effectively at the top 50 than the transparent rule baseline. It does not establish that refresh actions cause recovery or that the model predicts future Google rankings.

7. Ranked recommendations

  • refresh_and_review_ctr: inspect title/snippet alignment and search intent; verify impressions, clicks, CTR and position.
  • refresh_and_review_engagement: inspect content usefulness, page experience and whether visitors find the answer.
  • refresh: compare the page with current intent and competing coverage; update only where an editor finds a substantive gap.
  • expand_and_refresh: consider missing coverage or thin content, but verify the page's purpose before expanding.
  • monitor: retain in monitoring rather than spending immediate editorial effort.

Verify each page manually in the authorized editorial system. Never infer page identity from pseudonymous IDs. Do not automatically change titles, publish content or delete pages based only on a score.
